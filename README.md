# 望云

看**形**从**关系**里长出来的观测器。

不是求解器，不是可视化工具。它做的事只有一件：给一组关系和一个种子，让数值沿关系传下去，
然后让你看见——类型是怎么从一堆乱数里长出来的、长出来之后能活多久、什么时候可以信、
什么时候只是视角太粗。

设计文档在 [DESIGN.md](DESIGN.md)（本体、时间、视角、模糊两型、契约、25 个实文章节）。这里只讲怎么跑。

---

## 一分钟读懂它

**给它一张图，它会按顺序回答五件事：**

1. **这图有没有瓶颈**（`可读性: contrast / q_excess / dispersion` → 能读 / 勉强 / 别信）
2. **有几块、谁跟谁一块**（`k(r)` 的台阶 + `groups.csv` 的成员表）
3. **这些块有多紧**（同一尺度下比 `span`，不同尺度不能比）
4. **它们能活多久**（`t ≈ modules/(alpha·r)`，寿命由弱关系和走路规则定）
5. **数字信到第几位**（稳定前缀长度，上限由 kick 和你的表示法定）

**它不肯做的事**（边界写死，不要指望它）：不给唯一答案、不做预测、不优化任何目标、
不在一次跑里同时给你「结构活得久」和「精度高」——那两件事在机制上互相换。

**它最常被误用的地方**：把 `k(r)` 某一个数字当结论。一个数字里藏着三种东西（台阶位置、抽签、
tick 数），所以报 `k` 必须连 `k(r)` 整条曲线、tick 数、和可读性一起报。

## 三个读数

一次 4000 tick 的实测（n=128, seed=7, kick=1e-6）：

```
k: 119 -> 5          类型数从几乎 128 塌到 5 个
k(r) = [17, 8, 8, 8, 6, 3, 1, 1]   分辨率从细到粗，8 这一段是平台，宽 1.0 个数量级
stable: 0.31 -> 3.37 稳定前缀长度在长——数一点一点定下来
defect: 0.2561 -> 5.82e-05  违约读数，残差相对量级
```

（`stable` 只按**最近还在算**的单位平均。没被碰过的单位位数当然一位没变，但那是没算，不是稳。）

三件事分别对应三个问题：

1. **k(t) 往下塌** —— 类型是长出来的，不是给的。初值里没有任何模块信息（有测试守着这一条）。
2. **k(r) 有平台** —— 平台宽度 = 结构对比度（群间差/群内差）的对数。没有平台就没有结构，只有噪音。
3. **稳定位数往上爬** —— 前缀是「还能信到第几位」，尾部一直留着（幅度、方向、是否收窄）。省略的是位，不是过程。

### 稳定位数的上限（`law` 子命令实测）

```
稳定位数 ≈ min( 结构底 , 扰动决定的位数 )
扰动决定的位数 ≈ 0.86 · log10(1/kick) + 0.61     （kick ≥ 1e-2）
```

斜率 ≈ 1：kick 小十倍，多信一位。这就是「1.01 / 1.001 / 1.0001」那个现象——
**前缀的长度被「还有多少东西在动」定死，不是被「算得准不准」定死**。
1500 tick 时结构底是 3.21 位；跑得越久底越高（16000 tick 到 4.7 位）。
扰动太大还会打碎结构本身：kick=1e-1 时 k 跳到 21。

## 一个 tick 是什么

一次**不重复的传播**。从源 A 出发，每步走**欠得最多的那条关系**（`比例 × |值差|`），
走到「下一步会踩到走过的单位」就停。A→G 是一个 tick，G→A 不走。环被切断是因为
**A 是输入，不是解**。

代价被路径长度封顶（≤ n），和 n² 没关系。

两个「别这么干」的教训，都记在 DESIGN.md §9：

- 源 A **轮转**（`tick % n`）。别挑「残差最大的那个」——试过了，那是反扩散的，系统会由自己最坏的部分驱动（§9.1）。
- 走路时别只挑「比例最大的邻居」——比例是静态的，那样大部分源会汇进同一条走廊，
  少数单位一辈子轮不到被弛豫（n=2048 时访问次数 min 1 / 中位 52 / 最大 2017，defect 卡在 3e-2 不动）（§9.6）。

## 两型模糊必须分通道

- **A 型**：还没算到 / 还没稳住 → 点阵、抖动。含义是「别信这里」。
- **B 型**：视角太粗 → 干净平滑的轮廓。含义是「可信，但这就是这个尺度上的全部信息」。

混在一起就是撒谎：用户分不清「我不知道」和「我知道到这里为止」。

## 形状是怎么摆出来的

环上排开只是占位。现在的位置是**群间关系强度**解出来的：

```
W[i, j] = 群 i 的成员指向群 j 的那些关系的平均比例
```

弹簧模型：斥力 `k²/d²`、引力 `W·d/k`，平衡距离 `d ~ k/W^(1/3)`——关系强就挨得近。
三条硬规矩：只读 k×k（成本 k²，看不见 n）；强度只比相对（整体乘 100 给同一张图）；
取解按 `(交叉数, 能量)` 排序（8 点成圈时「环」和「八角星」能量一样低，但星读出来是错的拓扑）。

粗视图定形、细视图填细节：布局算在最粗的、还看得见结构的视角上，更细的从它广播下来。
反过来（细→粗取重心）会让细尺度的小错被粗视图继承，缩放时画面会跳。

## 拿它读一张图

单位数、模块数、模块内结构都不动，只改**模块之间的外连连成几个环**：

```powershell
& $py -m wy.cli run --n 128 --ticks 4000 --seed 7 --inter-cycles 2
```

| cycles | k(r) | 平台 | stable | 稳住 |
|---|---|---|---|---|
| 1（一大圈） | [17, 8, 8, 8, 6, 3, 1, 1] | k=8 | 3.45 | 0/8 |
| 2（两个圈） | [11, 8, 8, 8, 7, 2, 2, 2] | k=8 | 3.86 | 1/8 |
| 4（四个圈） | [10, 8, 8, 8, 5, 4, 4, 4] | k=8 | **5.21** | **4/8** |

**k(r) 有两级台阶**：细的那级永远是 8（模块），粗的那级正好是 cycles（连通块）。没有模块标签、
没有连通性信息、初值是乱数——粗尺度上的 k 回到连通分量数，中间那一段才是长出来的。

拆得越碎，位数越多、越早稳住（每块只跟自己玩），但「整张图」这个对象也就没了。
所以「读到几位」永远要带上「在哪一块上」。

**别信中间那级台阶的具体数字。** 同一设置换种子重跑（seed 7/8/9，连续分组与随机分组各一次），
最粗那两级永远是 `2, 2`——连通块数由拓扑定，稳。中间那级在 **6~8 之间跳**，跟分组方式无关：

```
[11, 8, 8, 8, 7, 2, 2, 2]   seed=7 连续
[12, 8, 7, 7, 5, 3, 2, 2]   seed=7 随机
[11, 8, 7, 6, 6, 4, 2, 2]   seed=8 连续
[21, 8, 8, 8, 7, 4, 2, 2]   seed=8 随机
```

信「有个台阶」和台阶的宽度，别信台阶的具体数字。写「k(r) 在模块尺度上有平台」是对的，
写「望云测出 8 个模块」就是把抽签当结论了。

### 让一个模块偷偷变松

```powershell
& $py -m wy.cli run --n 128 --ticks 4000 --seed 7 --weak-module 0 --weak-lo 0.01 --weak-hi 0.03
```

只把模块 0 的内部比例从 0.7~1.0 降到 0.01~0.03，别的都不动。以为会读到 k=7，实际是：

```
k(r) 从 [17, 8, 8, 8, 6, 3, 1, 1]（有平台）  变成  [28, 18, 9, 8, 6, 2, 1, 1]（没平台）
```

**没有 7。** 台阶直接没了——`k(r)` 是全局读数，一个地方不合格，不是把答案减一，是让整条曲线失去台阶。

要定位得看群表（`out/groups.csv`）：那一行 32 人、span=49，别的 16 人组 span=1.2~1.6，差三十倍。
松掉的团没被识别成「弱」，它被邻居吸收了（模块 0 和 1 并成 32 人组），然后整圈重新配平。

**k 是温度计，群表是 X 光。** 温度计说发烧，X 光说哪儿。

### 谁在干活：关系负荷

```powershell
& $py -u tools\load.py --ticks 4000 --window 100
```

到现在为止所有读数都是按**单位**记的。关系是本体、单位只是端点，可「哪条关系在干活」一直看不见。
现在每 tick 弛豫时，把这条关系实际搬了多少值记在它头上（`load[u, j] += |Δ|`）。

| tick | 搬运 | 活跃边 | 集中 | 换人 | 群外份额 |
|---|---|---|---|---|---|
| 100 | 4.7e5 | 512 | 0.397 | — | **1.0%** |
| 200 | 1.0e4 | 454 | 0.305 | 0.968 | **43.2%** |
| 1000 | 6.8e3 | 508 | 0.359 | 0.300 | 50.5% |
| 2000 | 2.9e3 | 492 | 0.366 | 0.345 | 48.0% |

**弱关系搬了一半的活。** 群外关系只占 25% 的条数、比例总和只占 0.16%（比群内弱六百倍），
却搬了 48% 的值——而且这个换班是突然的：头 100 tick 只搬 1%，100~200 tick 之间翻到 43%。

原因是走动规则 `score = 比例 × |值差|`：群内一收敛，值差塌到 1 上下；群外是模块之间的高度差（几百），
把两百倍的比例劣势抵回来还多。**拆结构的不是噪声，是这条路自己的选择规则**——这就是「结构有寿命」的机制。

两条口径：负荷只在还在动的时候有定义（搬运掉到 0，集中和换人报 nan，不报 0）；
集中平坦在 0.30~0.40、换人一直在 0.3~0.5（随机两个集合的期望是 0.95），
说明「谁在干活」由拓扑定，收敛只改总量不改分布形状。

**关系的寿命：两代。** 摊开每条关系的时间序列（`tools/load_life.py`），看它的「重心时刻」：

| | 条数 | 重心 | 中位 | 末窗仍活 |
|---|---|---|---|---|
| 群内 | 384 | 416 | 319 | 378 |
| 群外 | 128 | 1324 | 1372 | 128 |

重心前三分之一里，群内 171 条、群外 **0** 条；后三分之一里，群外 **全部 128 条**。
内部关系是开荒的（头几百 tick 把各自模块磨平就收工），外部关系是干长久活的。

**焊接压不掉跨群的活。** `--feedback 0.05` 开到底：群外比例从 0.0042 压到 **0.0010**（128/128 全在地板），
群内从 0.850 收到 0.988，可跨群关系干的活一点没少（48% → 53%）。因为选路是 `比例 × 值差`，
比例压到底之后由**值差**接管——那是结构自己维持的，掐不掉。

**焊接前后的 defect 不可直接比**：残差按比例加权，改了比例就改了残差的定义。
焊接后 defect 从 5.8e-5 掉到 3.0e-5，不是「和解得更好」，是「欠账被记到权重更小的关系头上」。

### 诊断带：事件和读数对到同一根竖线上

```powershell
& $py -u -m wy.cli strip --n 128 --ticks 4000 --seed 7
```

上排是事件发生那几 tick 的形状，下排是 k(t) / 违约读数 / 跨群负荷 / 稳定位数 / 色相移动五条曲线，
每一次划分变化画一根竖线贯穿（▼=并 ▲=分）。

读法就两种：竖线**密**的一段是结构在重排（并分交替），**稀**的一段是结构在稳定地并掉。
曲线在竖线处的台阶是真的；竖线在而 k 没台阶，说明那次是局部换人、不是总数变了——这两种别混读。

最底下那条「色相移动」是按人算的短弧总量：非零的格正好落在竖线上，说明这一刻真有人换了色。
它和 k(t) 的温度不一样——分开也可能很疼（一大团里走掉三分之一，每人挪一格），
所以看它问「谁换了色」，别问「哪次最剧烈」（§30.5）。尖上的小点颜色跟 ▼/▲ 走（并=橙、分=青）。

上排缩略图也按成员记色：同一批人从这一格到下一格不换色，只有换群的那几个挪（§30）。
不然同一批人会在讲事件的这张图里自己变颜色。

一条纪律：缩略图和曲线必须来自**同一次演算**（同种子、同参数、同 tick）。两次跑凑出来的对齐图更好看，
但那是在两套事实上画竖线。

### 结构活多久：`t ≈ modules/(alpha·r)`

```powershell
& $py -u tools\lifetime.py
```

弱耦合比例 `r` 越小，结构活得越久，近似**反比**（实测斜率 1.06，n=256 时 1.03）。
常数别省：写 `t ≈ 12·(1/r)` 或 `modules/(alpha·r)`，写「t ≈ 1/r」会差一个数量级。

量这个数有一个坑：`k(t)` 开头会**假塌**——随机初值还没分开，2% 档先把它们并成几团。
所以三个时刻都从「最后一次还看得见整套模块」之后算起，否则量到的是开头那段。
顺带一条：**「最后的分」总是早于「塌成一团」**，结构先停止重排，再慢慢合上。

### 想让结构活久一点：`--walk-power`

`score = 比例 × |值差|` 里，群内收敛后群的弱关系靠大差值抢活干（§16），结构就被自己拆掉了。
把比例的指数调大等于给弱关系打折：

```powershell
& $py -u -m wy.cli run --n 128 --ticks 4000 --seed 7 --walk-power 2
```

γ 从 1 到 2：群外负荷份额 45.9% → 26.4%（25% 的关系就该拿 25% 的活），覆盖 min 10 → 72，
结构寿命（`t(k≤2)` 三种子均值）3193 → 8240，约 **2.6 倍**。

代价是违约读数停在 8.1e-5（γ=1 时 5.8e-5）——结构活着，就是有差别还没抹平。跟 §10.2 同一条交换。

默认仍是 γ=1：它不是「差的默认值」，是另一格刻度。要长寿命就显式拨，拨了要记住交换比。

### 形长齐了吗：看平台宽度，别看稳住了几个

```powershell
& $py -u tools\settle.py                  # γ=2
& $py -u tools\settle.py --walk-power 1   # 对照
```

稳住的群数会**饱和**（两条路最后都能到 6~7 个），用它可以，但分辨不出差别。
分辨力在 `k(r)` 里 modules 那一档**跨了几个数量级**：

| | 4000 | 8000 | 16000 | 32000 |
|---|---|---|---|---|
| γ=2 的 8 档宽度 | 1.00 | 1.00 | **1.48** | 0.00 |
| γ=1 的 8 档宽度 | 1.00 | **0.48** | 0.48 | —（八档全 1） |

还有一条：**塌也要带尺度说**。32000 tick 时 γ=2 的粗档全塌了，可 1e-4 那一档仍读到 8——
留下的是 8 级几乎重合的台阶，7 个群内部还稳着。γ=1 那时八档全是 1，连台阶都没了。

所以「长齐」写成句子是：**modules 那一档跨过至少一个数量级、且其中过半群已稳住。**

### 一个连通块里住着两种形

```powershell
& $py -m wy.cli run --n 128 --ticks 4000 --seed 7 --weak-set 4,5,6,7 --weak-lo 0.10 --weak-hi 0.20
& $py tools\two_shapes.py --weak-lo 0.10 --weak-hi 0.20
```

模块数、连通块数、拓扑全都不动，只把 4~7 这四个模块内部压松一档。结果是**两档密度没有重叠**：

| 弱模块内部比例 | k(r) | 平台 | 紧的群 span | 松的群 span |
|---|---|---|---|---|
| 没压 | [17,8,8,8,6,3,1,1] | k=8 | 1.4~3.0 | — |
| 0.30~0.50 | [58,14,8,8,7,4,1,1] | **k=8** | 1.75~2.02 | 4.57~6.52 |
| 0.10~0.20 | [39,17,9,8,6,2,1,1] | None | **1.51~2.28** | **9.67~36.64** |

三句话：

- **k 看不出有两种。** 0.30~0.50 那档平台还是干净的 k=8，好像八个模块一样紧；0.10~0.20 时平台干脆抖没了。
- **span 看得出。** 一个模块一个群的群里，紧的 1.5~2.3、松的 9.7~36.6，差 5~20 倍，不重叠。
- **span 有比例尺。** 两个模块并成的 32 人群 span 天然 26~37——那是两个不同高度的团被并在一起，不是「松」。
  比 span 之前先确认两个群一样大。

望云不给「A 型 32 个、B 型 96 个」这种标签，它给一张群表，让两档密度自己浮出来。

### 把两种形分开放：粗视角只报块，不报松紧

```powershell
& $py -m wy.cli run --n 128 --ticks 4000 --seed 7 --inter-cycles 2 --weak-set 4,5,6,7 --weak-lo 0.10 --weak-hi 0.20
& $py tools\two_shapes.py --cycles 2 --weak-set 4,5,6,7 --weak-lo 0.10 --weak-hi 0.20 --frac 0.1
& $py tools\two_shapes.py --cycles 2 --weak-set 4,5,6,7 --weak-lo 0.10 --weak-hi 0.20 --frac 0.01
```

两个连通块，模块 0-3 一圈（紧）、4-7 一圈（压到 0.10~0.20）。以为粗视角能读出「一个块紧一个块松」：

| 视角 | 都不压 | 4-7 压松 |
|---|---|---|
| 粗 0.1 | 206.6 / 150.2 | **206.6 / 227.6** |
| 中 0.01 | 0.86/0.68/1.63/1.01 + 并掉一团 16.1 | 紧 **0.86/0.68/1.63/1.01**；松 **7.57/2.93** + 并掉一团 21.1 |

- **粗视角读不出松紧**：什么都没压，两个块的 span 就已经差 38%（206.6 vs 150.2）——那是块与块之间的
  高度差，不是松紧。松紧在粗尺度上是零头。
- **中视角才分得出**：紧的 0.7~1.6、松的 2.9~21.1，无重叠。
- **动一个块，另一个块逐位不变**：紧的那块 span 两次都是 206.599。两个连通块之间没有任何关系。

每个尺度只说那个尺度的话。粗视角能说的只有「这里有两个块」。

## r 能一直往下调吗：不能

```powershell
& $py tools\ladder.py --ticks 4000 20000
```

`k(r)` 是阈值读数：差得比 r 近的单位算一团。既然所有结论都靠它，就得问一句——r 往小里调，会读到更细的结构吗？

| frac | 1e-2 | 1e-3 | 3e-4 | 1e-4 | 3e-5 | 1e-5 | 3e-6 | 1e-6 |
|---|---|---|---|---|---|---|---|---|
| 4000 tick | 6 | 8 | 8 | 17 | 67 | 107 | 121 | 128 |
| 20000 tick | 1 | 1 | 4 | 7 | 8 | 8 | 9 | 32 |

**不会。** 阶梯没有噪声底，它一路爬到 n（128 就是「每个单位都跟自己不一样」）。台阶以下读到的不是更细的结构，
是单个单位的小数点后第几位。

顺手量到一件出乎意料的事：**换数值表示对 k(r) 一格都没改**。float64 和 `--exact` 整数演算逐格相同——
结构里的差量级在 1e-6~1e-9，比 float64 的 ulp 还高好几个数量级。表示只影响「位数」那条读数，不影响「有几团」这条。

所以 `k(r)` 只在**有一段平坦**的时候才有意义，判平的是 `plateau()`，把阶梯画长一点不会多出结构，只会多出一段斜坡。
默认的 `FRACS` 下界 1e-4 是经验边界：4000 tick 时刚好还在台阶上，20000 tick 时台阶已经没了、整条都是斜坡。

**报 k(r) 必须同时报 tick 数**——跟只报位数不报量尺是同一类错。

## 跑长了会怎样：位数有天花板

```powershell
& $py -m wy.cli run --n 128 --ticks 100000 --seed 7
```

```
k: 119 -> 1     stable: 0.31 -> 6.14     defect: 0.2561 -> 6.432e-08
k(r): 全档都是 1     partition 已经 94237 个 tick 没变过
```

6.14 位，而 `--kick 1e-6` 就是 log10(1/1e-6)=6 位——**差 0.14 位，就是没收完的那点尾巴**。

| kick | 20k tick | 100k tick | log10(1/kick) |
|---|---|---|---|
| 1e-3 | 3.34 | — | 3 |
| 1e-4 | 4.45 | — | 4 |
| 1e-6 | 5.21 | **6.14** | 6 |
| 1e-9 | 5.52（时间不够） | — | 9 |

三件事：

1. **天花板是 kick 定的，不是时间定的。** 再算也就到 6 位。你信几位，取决于你还往里浇多少不确定。
2. **时间只决定「到没到天花板」。** 报位数必须同时报 tick 数，否则「5.5 位」是天花板还是半路，读的人分不出来。
3. **形先死，位数后到上限。** 十万 tick 时结构早塌成一团，位数还在往上爬——想看形别跑那么久，想量精度那时已经没形可看。

### 两个假天花板：量尺，和「冻住」

```powershell
& $py -m wy.cli run --n 128 --ticks 200000 --seed 7 --kick 1e-15 --digits 18
```

`--kick 1e-15` 一开始读出 13.000，以为撞上 float64——**是尺子到头了**（默认 `digits=12` 最多数到 13 位）。
放长量尺再跑，同一份演算是 **15.70**。

| kick | stable | log10(1/kick) | defect 地板 |
|---|---|---|---|
| 1e-12 | 12.02 | 12 | 6.1e-14 |
| 1e-13 | 13.02 | 13 | 7.2e-15 |
| 1e-14 | 14.30 | 14 | 6.5e-16 |
| 1e-15 | 15.70（400k tick 时 16.37） | 15 | 1.4e-16 |

那个 16.37 不是算准了十六位：**稳定位数只问「这几位多久没动过」，值冻住的时候它当然没动过。**
增量掉到可表示精度以下，值停在原地，位数就一路爬到量尺顶。曲线看着越来越稳，实际越来越算不动。

所以 `run` 同时打一个**活性**：

```
活性: 最近在算的里面 24% 这一 tick 真的变了（太低说明是冻住，不是收敛）
```

三条口径：① 报位数必须报量尺（`--digits`，数到 digits+1 会警告）；② 报位数必须报活性；③ float64 的实际天花板在这个尺度上 ≈ 15 位。

### 那 15 位是世界的天花板，还是 float64 的？

换一套数值表示就回答得掉。`wy/exact.py` 把值存成 10⁻³⁰ 的整数、系数存成 10⁻²⁴ 的整数，
更新全是整数除法——没有舍入累积，只有「这一步截掉了多少」，量级 10⁻³⁰。
**`run` 本身就能换表示**，加 `--exact` 即可：

```powershell
& $py -u -m wy.cli run --n 128 --ticks 4000 --seed 7 --exact
& $py -u tools\deep_exact.py --ticks 400000 --kick 1e-18
& $py -u tools\reconcile.py
```

两种表示跑同一条命令，k、defect、k(r)、plateau、三档 LOD 逐项相同（位数会有差别，那是
轨迹本身对舍入敏感，不是实现不一致）：

| | kick=1e-15, 200k tick | kick=1e-18, 400k tick |
|---|---|---|
| float64 | 15.70，但 vmin==vmax==4785.4187，活性 44/128（冻了） | 读不出来 |
| 整数演算 | **14.66**，活性 128/128 | **18.06**，活性 128/128 |

- **15 位是表示的天花板。** 换掉之后 kick=1e-18 读出 18.06 位，而且每个单位每 tick 都还在动。
- **float64 的 15.70 是假读数**：值已经冻成一个数，「最近没变」当然成立。真实位数比它报的低。
- **位数上不去的主因是时间**：缺陷大约每 10³ tick 掉一个数量级，到 18 位要几十万 tick。
- 顺带得到一条硬东西：整数演算是**逐位可复现**的，跨机器一致——「回放 = 重算」在它上面是真的。

两套实现独立写，同种子跑前几十个 tick 相对误差 9.2e-17（机器精度），之后会因舍入敏感而分岔
（`tools/reconcile.py` 能看到第几步分开）——那是这套演算本身的性质，不是实现 bug。


## 看它怎么变（`evo`）

`evo` 把同一份关系在若干 tick 上的形状连成一条带子，落 `out/evolution.png`。两种采法：

- `--mode even`：等间隔采，看整体节奏。
- `--mode events`（默认）：**只在划分真变了的那一 tick 采一帧**，标题写清并了谁/分了谁，并把刚并进来、
  刚裂开的那几团圈出来。看的是「它为什么变」，不是「它在变」。

规矩：

- **采样，不是动画**：每一帧都是那一刻真算出来的群表，不补中间态。
- **位置记路**：按成员重合把上一帧的坐标搬过来，再转回上一帧的朝向。弹簧只定「谁离谁近」，
  整体转个角度对它是同一个解——但人眼看的是连续，画面跳一下就会被当成结构变了。
- **看哪一档是选出来的**：在候选分辨率里挑「整段时间里划分最稳」的那一档（相邻帧 k 变化最小、每帧 k ≥ 2）。
  用终态的 k(r) 平台档会看到阈值在抖，那不是结构在变。
- **按人认，不按下标认**：判「并」要过半（一个旧群超过一半成员进了同一个新群才算整体过去）；
  圈谁也得用成员集合去群表里对——群表是按 gid 重排过的，拿事件里的下标去圈会圈到别的群，而且看着像真的。
- **只在长成形之后挑事件**：k 还上百的时候全是小球互并，圈出来是一团糊。`--max-k`（默认 24）把事件池
  限制在 k 已经降下来的那一段。

一次 4000 tick 的带子（`events` 模式 8 帧，共 140 次划分变化）：

```
t=17   并 2→1  k 24→23      t=37   分 1→3  k 12→13
t=76   分 1→2  k 8→10       t=193  并 2→1  k 9→8
t=342  分 1→2  k 7→8        t=517  分 1→2  k 6→7
t=800  并 2→1  k 7→6        t=3294 并 2→1  k 5→4      defect 2.21e-4
```

`defect` 一直单调往下，`k` 先塌后抖——**形先长出来，再慢慢散掉**。并和分是离散地一步一步发生的：
前 800 tick 里并、分交替（结构在重排），800 tick 之后到 3294 tick 只发生了一次并（结构在慢慢地磨平）。
等间隔的 `even` 模式看到的是同样的事，只是看不出「哪一步是谁跟谁」。下面这组是 `even` 8 帧：

```
t=500  k=7   →  t=1000 k=5  →  t=1500 k=6  →  t=2000 k=5
t=2500 k=5   →  t=3000 k=4  →  t=3500 k=4  →  t=4000 k=4
defect: 1.86e-3 → 1.96e-4
```

## 让它反过来（`--feedback`）

DESIGN §7 第 4 条那个「形是单向还是双向」，现在是**可开的双向**，默认关：

```powershell
& $py -m wy.cli run --n 128 --ticks 12000 --seed 7 --feedback 0.05
```

规则：某个成员集合连续 64 个 tick 没变过（`--feedback-age`），它才算「站住了」；站住的群每 25 个 tick
做一次收紧——群内关系往 1 推、群外往 0 推。**只有已经站住的形才有资格改关系**，早期乱划的群不许动手；
整张图是一个群时也不动手（那不是结构，是同质化的前身）。

实测（`tools/compare_feedback.py`）：

| ticks | 反馈 | k 终值 | k(r) | 平台 |
|---|---|---|---|---|
| 8000 | 关 | 1 | [8,8,8,8,3,1,1,1] | k=8（细尺度） |
| 8000 | 0.05 | 4 | [5,5,5,5,4,3,1,1] | k=5 |
| 12000 | 关 | **1** | [8,8,8,4,1,1,1,1] | k=8（细尺度） |
| 12000 | 0.05 | **2** | [3,3,3,3,2,2,1,1] | k=3 |

两句话：

- **正反馈把结构焊住了**。静态关系 8000 tick 之后 2% 那档已经并成一个，开了反作用还剩 4 团。
- **代价是违约读数下不去**（9.4e-6 vs 7.0e-6）。关系拉紧之后，没抹平的差别更显眼——结构活得久，
  就意味着系统一直保留着没和解的部分。这两个数是同一件事的两面。
- **别一直焊**：12000 tick 时一直焊只剩 2 团，焊到 4000 就停反而有 4 团（见下一节）。

还有个坑：认群必须用**细**档。用粗档时整张图早早就是「一个群」，一起加固，反而把 8 团并成 2 团。

### 别一直焊：焊到一半就松手

正反馈的危险是把偶然焊死。`--feedback-until N` 只在前 N 个 tick 里收紧，之后关系冻住继续跑：

```powershell
& $py -m wy.cli run --n 128 --ticks 12000 --seed 7 --feedback 0.05 --feedback-until 4000
```

| 做法（12000 tick） | k 终值 | 平台 | defect | stable |
|---|---|---|---|---|
| 不焊 | 1 | k=8（细尺度） | 7.0e-6 | 4.16 |
| 焊到 t=4000 就停 | **4** | **k=8** | 1.40e-5 | 4.01 |
| 一直焊 | 2 | k=3 | 9.4e-6 | 3.73 |
| 自动松手（t=1850 停） | **5** | **k=8** | 1.46e-5 | 4.00 |

**焊够一次，结构就能自己活下去**：只焊了全程三分之一，终态 k=4，比一直焊的 2 还好；自动松手更省，
69 次而不是 156 次，终态 k=5。一直焊最差——焊接本身在把关系推向 1/0 两端，推到底之后细结构也被磨掉。
所以双向的正确用法不是一直开着，是**当一次退火**。

手填 N 不算办法，所以有了 `--feedback-auto`：每轮焊之前记一次违约读数，最近 8 轮的前后两半相对改善
小于 2% 就停手（`--feedback-tol` / `--feedback-win` 可调）。默认那跑是 t=1850 松的手。

**但松手位置是 tol 挑的**：tol=0.005 → t=3150、0.05 → t=1425、0.5 → t=400。所以报这个数得连 tol 一起报——
它是个「够用就停」的工程判据，不是「结构到哪天为止」的物理量。

三个读数是**互相换的**：焊得越久，关系越硬、结构越稳，但违约读数越高、能信的位数越少
（焊住的 r 大 → 每 tick 步长 `alpha·r·Δ` 大 → 低位抖得厉害）。望云不做「三者同时最好」，
它做的是**把这个交换比显示出来**。

## 大到 2048 个单位

```powershell
& $py -m wy.cli run --n 2048 --ticks 400 --seed 7
```

一开始要 **187 秒**，现在是 **4.8 秒**。三个地方：

| 阶段 | 改前 | 改后 |
|---|---|---|
| 一步演算 | 17.6 ms/tick | 0.82 ms/tick |
| 布局（k=307） | 20.2 s | 1.02 s |
| 画（k=1475） | 18.9 s | 几乎不要时间 |

- 走动内层从 numpy 改成纯 Python：一步只看 4 个邻居，为算这 4 个数付三次 numpy 调用不划算。
- 布局的步数和重启次数随 k 自适应，内部用 float32。
- k 太大就**不画**，画一层雾，并写明「视角太细，这个尺度上画不出形状」。`holes` 记 **−1**——
  0 是「数了，没有洞」，−1 是「这里没有读数」。

阈值不是用来省时间的，是用来承认「这个尺度上没有可读结构」。省时间是副作用。
**降级必须写在图上**：占位不许被当成结构。

## 契约（有测试守着的）

1. **可复现**：同数据 + 同种子 + 同参数 → 逐位相同。
2. **省略 ≠ 删除**：变的位只许压成摘要，不许扔。
3. **LOD 不矛盾**：`r2 > r1 ⇒ 划分(r2) 是划分(r1) 的粗化`（每个细群整个落在某个粗群里）。
   洞数**不是**契约——粗看时轮廓并起来会围出新洞，那是尺度换了，不是自相矛盾。
4. **一个 tick 的代价 ≤ n**，与 n² 无关。
5. **不改拓扑**：视觉系统不得增删单位和关系。

## 读一张真图（v3.1）

前 22 节全是自己造的图。这一节换真东西——《悲惨世界》人物共现网络，77 点、254 条带权关系，
节点自带 11 个参照分组（**分组不进入演算，只在事后对账**）。

```
python -m wy.cli read --edges data\miserables.txt --ticks 400
python tools\score_groups.py out\groups.csv data\miserables_labels.txt
python tools\probe_merge.py data\miserables.txt data\miserables_labels.txt --frac 2e-2 --targets 11 5 3 2
```

**读进来了**：度数不齐用自环补空位（走动时必定已被走过，选不中），`mask` 记着哪些格子是真的关系，
孤立点的残差记 0。比例按每个单位自己最强的那条归一——真图权重量纲一大，全部比例会趴到 0.01 以下，
一步只挪 `alpha·0.01·Δ`，几万 tick 都收敛不动。

**但读不出人给的组**（这是负结果，不是没跑通）：

| 图 | 最好 ARI | 群数 | 纯度 |
|---|---|---|---|
| 原图 | 0.28 | 26 | 0.71 |
| 对照组：跨组关系 × 1/1000（几乎切断） | 0.46 | 24 | 0.81 |

三条机制（DESIGN §22 有账）：

1. **真图的终态一定是 1 团**。连通图扩散到最后就是全局一致，20000 tick 时 `k(r)` 八档全 1。
   结构只活在过程里——**读真图必须报 tick 数**。
2. **单一全局半径要求各块「差不多紧」**。那 11 个组的组内离散从 5 到 180（差 20 倍），
   半径取小拆散紧组、取大并掉松组，**这个图上没有能用的半径**。跟 §14 是同一件事。
3. **`FRACS` 是按初值尺度取的**，真图收敛后对比度落在 1e-3…1e-2 那一窄段，八档网格太粗。
   「没有平台」有时是网格没采到台阶。

下一步（没做）：把判据从全局半径换成**相对半径**——每群按自己的 span 判它还在不在动。

## 相对半径：判据跟着群走（v3.2）

上一节那个失败的诊断是「一个半径伺候不了松紧差 20 倍的块」。换掉判据再试：

每个单位有自己的尺子 `s_u = median(|v_u - v_w|)`（跟邻居差的中位数），一条关系连不连看
`|Δ| ≤ τ × min(s_u, s_v)`——两端都认为「这一差算小」才连。

```
python tools\rel_read.py data\miserables.txt data\miserables_labels.txt --ticks 50 100 200 --mode min
```

| 图 | 最好 ARI | 说明 |
|---|---|---|
| 合成图（8 模块，3000 tick） | **1.00** | τ 1.5~3 全读出 8 个整团，是个平台 |
| 《悲惨世界》 | **0.34** | 全局半径是 0.28，抬了一点就停住 |

**同一个仪器、修好的判据，种下去的结构 ARI=1.0，真图 0.34。**
所以望云读的是**瓶颈**（切断它要花多少代价），不是**语义**（人按故事分的组）。
两者有时重合，有时不重合，它只认前一种。

## 先问它能不能读（v3.3）

任何一张图上，先算两个数（不需要标准答案）：

    contrast   = 跨群关系的平均比例 / 群内关系的平均比例     小 = 瓶颈陡
    dispersion = 群 span 的 p90 / p10                    大 = 各群松紧差得多

`cli read` 会先报这一行，再报读数：

```
可读性: contrast 0.901  dispersion 4.8  -> 别信：这张图的块不是被瓶颈分出来的
```

标定（把合成图的瓶颈一点点调弱，`tools/readable.py`）：contrast 0.074 时读数还是满分 ARI 1.00，
0.204 时掉到 0.17。所以 `≤0.10` 能读、`≤0.20` 勉强、再高别信。《悲惨世界》是 0.9——
**跨群的边跟群内的边一样重**，那就是没有瓶颈，读出来的划分只能是噪声切的。

## 真图之二：一台真机器的 npm 依赖图（v3.4）

《悲惨世界》读不出来可以用「没有瓶颈」解释。换一张真有瓶颈的：本机 Electron 归档里的
整棵 `node_modules`——592 个包、1657 条「谁依赖谁」，结构不是我造的。

```
python tools\asar_deps.py "D:\deepseek\resources\app.asar" --out data\deps.txt
python -m wy.cli read --edges data\deps.txt --ticks 400 --walk-power 2
```

可读性：`contrast 1.000`（权重全一样，这条尺子在这张图上量不出东西）、`q_excess +0.229`、
`-> 勉强`。**注意可读性也挑 tick**：同一条命令改成 `--ticks 200` 会报 `q_excess +0.133 -> 别信`——
它不是图的属性，是「这张图在这个时刻」的属性，必须连 tick 一起报。读出来最大的两团：

| 人数 | 家族分布 |
|---|---|
| **289** | `@deepseek-ai` **258 人（89%）** |
| **25** | `@aws-sdk` **17 人（68%）** |

这两团是图上真实的瓶颈（内部互相依赖、跨出去少），而且**没有任何标签进过演算**。
剩下的 180 多个小组是噪声——所以它报的是「勉强」，不是「能读」。

这一轮给可读性加了第三个数 `q_excess = 模块度 − 同尺寸随机划分的模块度`：
contrast 说权重有没有信息，`q_excess` 说这一刀真不真，dispersion 说是不是靠参数凑的。

## 画一张图（v3.5）

形本来就是输出端的一堆数值。这一条把它变成像素：

```
python -m wy paint --n 128 --ticks 4000 --seed 7
```

它跑一次演算，把读数映射成参数（群数 → 花纹，群内极差 → 眼睛大小，稳定位数 → 辉光，
违约读数 → 背景星），再按参数画图，落 `out/paint.png` 与 `out/paint.json`。

`paint.json` 里同时存了 `readings` 和 `params`——**图上的每个数都能追回到某次 tick 的某个读数**。
这是「用望云画图」和「用别的工具画图」的区别。

**指定像什么**：`--brief` 收一句人话，挑一组最接近的演算配置：

```
python -m wy paint --brief "大眼睛，少花纹，星空"
```

它先把你说的变成读数目标（眼大小/花纹/星），再在一组候选配置里挑一个，
挑不到会明说「在这个范围边缘」。可达区间（默认预算）：眼 0.22~0.37R、花纹 0.41~0.77、星 0.46~0.67——
**可指定的范围就是读数能表达的范围**。

**画它的场面**（不是肖像，是「这张图长什么样」）：每个群是一个物体，关系强的离得近、长得大：

```
python -m wy scene --n 128 --ticks 3000 --walk-power 2 --target-k 8
python -m wy scene --edges data/deps.txt --ticks 400 --walk-power 2
```

位置来自关系的弹簧布局，大小来自人数，实心/点阵来自稳不稳。没有「构图」这一步——
**画面是读数的函数**，不是画出来的。

**让它动起来**（采样，不插值）：

```
python -m wy anim --n 128 --ticks 3000 --walk-power 2 --frames 8 --gif scene.gif
```

每帧是某次 tick 的真实读数；位置按成员重合搬过来（群数变了也接得上），尺度沿用第一帧。
颜色也按成员重合记路：老群逐帧原色不动；并群时输掉的那半跳过去，分开时后面几个兄弟各挪一格——所以颜色变了，就是有人换了群，不是镜头在抖。
运行时会打一行「色相移动」，哪个 tick 有人被迫换色一眼能看见。
**紧的群长得像球，松的群长得像碎石头**——表面碎不碎由群内极差定，不是随手挑的。

**点开一个群**：

```
python -m wy drill --n 128 --ticks 3000 --walk-power 2 --frac-mid 1e-3 --top 6
```

群内部也是一张图：位置由成员关系定，大小由内部度数定，色相由「相对本群均值的高低」定。
它能看见 `k` 看不见的东西——这一团是不是其实该拆成两团。

**怎么读这些图**：见 GUIDE.md（两页判据表：五种图各回答什么、每个读数什么时候别信）。

边界：它是参数化肖像，不是绘画。笔触、层叠光斑、手绘边缘都做不到；
要更像，只能往参数表里加旋钮，或者换渲染后端（形还是那张表）。

## 没做到的（已知的洞）

- 视觉系统只画到「群摆成的形状」，还没到能直接喂给建模软件的网格；真正的形是 `groups.csv`。
- 稳定位数 4000 tick 才爬到 3.35，想看到实心群得跑到 1.6 万 tick 以上（那时 4.7 位）。
- 结构有寿命：8000 tick 时 k(r) 还留着 8 的平台，12000 tick 已经塌成 1（开 `--feedback` 能拉长，见上一节）。
- 双向目前只有一个强度旋钮和一个「焊到哪天为止」；正反馈会不会在别的参数下把偶然锁死，只在这个种子、这组参数上测过。
- 没测过十万 tick 以上数值精度会不会被磨掉。
- n 再往上（比如 8192）没试过；2048 时中档视角已经有 188 个团，再多就只能靠收视角了。
- 真图还没读出名堂：相对半径把它从 0.28 抬到 0.34，然后停住（DESIGN §23）。仪器没问题，是「瓶颈」和「语义」不是一回事。
